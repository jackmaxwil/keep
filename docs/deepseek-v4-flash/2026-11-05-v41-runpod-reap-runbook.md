# DeepSeek-V4.1-Flash REAP on RunPod: runbook

Date: 2026-11-05. Budget: $497. Kit: `scripts/runpod/v41_reap/`.

## Goal

The V4-Flash artifacts are gone. This run makes new V4.1 artifacts on rented
GPUs so that the Mac downloads a smaller, pruned checkpoint instead of the
510 GB source.

| Output | Where (on the volume) | Size (est.) | Used for |
|---|---|---|---|
| Pruned HF checkpoint (FP8 dense, FP4 experts, Engram, drafter untouched) | `/workspace/v41-reapN/` | ~366 GB at N=192, ~342 GB at 160 | V4.1 port, E8P conversion |
| REAP stats, survivor tables, reap-select reports | `/workspace/out/` | < 50 MB | prune choice, hot set |
| Route traces (first 2,048 tokens of each session) | in each session npz | small | residency replay (SSD tier) |
| E8P importance stats (imatrix `hidden` + `down`) | `out/calibration/sessions/*.npz` | ~0.9 GB per session, ~25 sessions | E8P/VQ fitting (`finalize`) |
| Teacher top-2048 logits for the eval split | `out/eval/sessions/*.npz` | ~5 GB | KL gates, MTP and distillation |
| Candidate scores (KL, NLL change, top-1 agreement per domain) | `out/candidate-scores.json` | tiny | choosing N |

## What is verified, and what is not

**Verified on CPU on this Mac**, in 7 tests in `tests/test_runpod_v41_reap.py`
plus a manual end-to-end:

- The patched `MoE.forward` gives bit-identical output to a copy of the
  reference Gate/Expert/MoE.
- REAP and imatrix sums match a direct float64 computation.
- KEEP's own validators accept the session files, and `finalize-reap`,
  `reap-select` and `finalize` run unchanged on them.
- The head capture matches full logits.
- A masked-router student scored against its own teacher gives KL 0.
- The pruner copies bytes exactly, renumbers experts, slices `weight`, `bias`
  and `bias_vl`, and leaves `mtp.*` alone.
- The pack builder keeps eval and calibration groups disjoint and drops
  non-English text.
- Real rows from Open-SWE-Traces, Nemotron-Terminal and Toucan render through
  V4.1's own `encoding.py` and tokenizer.

**Not verified until the pod runs:**

- the reference code under torchrun with 8 GPUs and NCCL;
- throughput (`progress.jsonl` reports tok/s per session);
- GPU memory headroom at 16K tokens;
- that each dataset streams with the field names assumed. They were checked
  against one row of each via the HF datasets-server.

## Calibration mix

The research is in `docs/research/2026-11-05-v41-reap-calibration-data.md`. In
summary:

- **Size:** about 3.2M calibration tokens and 0.45M eval tokens.
- **Language:** English only. A record is dropped if it contains any CJK,
  Hangul or Kana, or more than 2% of its letters are outside Latin.
- **Agentic and tool-loop share:** 60%. The sources are:
  - Open-SWE-Traces (DeepSeek-V4-Flash-0731 OpenHands trajectories; Python 400K, TS 300K, Rust 300K);
  - SWE-rebench-V2 PRs as issue-to-patch pairs (400K);
  - Nemotron-Terminal (400K);
  - Toucan multi-turn MCP traces (450K).
- **The rest:**
  - cyber: CIRCL advisories plus security StackExchange, 300K;
  - networking: RFC 9000-9800 plus networkengineering, serverfault and unix StackExchange, 250K;
  - business: finepdfs business-filtered plus Enron, 250K;
  - English: WildChat human prompts plus finewiki, 150K.
- **Held-out split:** one group bucket in ten goes to eval. Groups are
  repository, task, RFC, URL host, CVE and tool set.

Differences from the research mix:

- **No Primus-FineWeb.** It is gated.
- **No WildChat responses**, only the human prompts. The responses are OpenAI
  output.
- **No stackv2 plain-code files.** The shards have no language index, so I
  doubled SWE-rebench PRs instead.
- **No 32K-64K long slice.** `--max-seq-len` is 16384. Longer records are
  truncated, not windowed.
- **Assistant turns are not regenerated by V4.1.** That would add a generation
  stage, so it is a follow-up.

Jack's five candidates:

- Open-SWE-Traces is the top source.
- CoderForge is suited to eval only and is not used yet.
- Vyber07/cyber-security, Fable-5.1 and Axion are rejected. Fable-5.1 is
  Claude-distilled with placeholder tool arguments.

## Single-pod mode (what actually ran, 2026-11-06)

On 2026-11-06, 8×H200 was out of capacity in every data center that offers
network volumes, so everything runs on one 8×H200 pod with a 2 TB volume disk:

```bash
MAX_GPU_HOURS=8 bash /workspace/keep/scripts/runpod/v41_reap/pod.sh all
```

That command runs these steps:

- **fetch and pack:** run in parallel.
- **convert:** writes the TP8 checkpoint.
- **teacher pass:** runs over the pack.
- **scoring:** checks N = 256/192/128/96.
- **cleanup:** deletes the TP8 checkpoint.
- **prune:** writes REAP 50% (N=192, ~366 GB) and REAP 75% (N=96, ~293 GB).

The pod stays up so the Mac can pull the results. The watchdog stops it at
8 h, and a failed stage stops it at once.

The Mac cannot hold both checkpoints at once (423 GB free), so pull one at a
time.

## Getting an 8×H200 pod (lessons from 2026-11-06)

No 8×H200 pod could be created on 2026-11-06, even though the catalog listed
stock. These are the lessons from that day.

**Tools:**

- **Use the official Runpod plugin.** Install it with
  `claude plugin marketplace add runpod/runpod-plugins-official` and
  `claude plugin install runpod@runpod`, then sign in through `/mcp` →
  runpod. It signs in with OAuth, so no API key ends up on disk. Its MCP tools
  are REST v2 and read live state.
- **Check stock for the GPU count you need:**
  `get-gpu-type id="NVIDIA H200" include=AVAILABILITY product=POD count=8`.
  This returns stock per data center, the host CUDA versions that have
  capacity, the minimum RAM and vCPU, and `maxCount`. `runpodctl gpu list` is
  not enough: its `stockStatus` is the best status across all data centers and
  is counted for a single GPU.
- **Get the price and CUDA matrix for many types at once:**
  `get-capacity gpuCount=8`.
- **Create the pod with REST v2 `create-pod`.** The body must include `disk`,
  `mounts` or `templateId`. Without one of them you get *"You must either
  provide a template id or pod configuration parameters"*.

**What the catalog showed, and what happened:**

- **Catalog:** 8×H200 secure was "Low", only in EUR-IS-5 and only on CUDA 13.2
  hosts, at $5.29/GPU/h ($42.32/h). Those hosts had 1510 GB RAM and 160 vCPU.
  B200, H200 NVL and every H100 variant showed no 8-GPU stock.
- **Every H200 create failed with the same 400** (*"There are no longer any
  instances available"*):
  - with the host specs pinned (`allowedCudaVersions`, `minRamPerGpu`,
    `minVcpuCountPerGpu`);
  - with 1400 GB and 1100 GB volume disks;
  - with community cloud;
  - with no data-center filter;
  - with a bare single H200.
- **The control worked.** A 1×RTX 4090 with the same image and ports was
  created at once. So the account, the image (`runpod/pytorch:1.5.0-cu1281-torch291-ubuntu2404`)
  and the request shape were all fine; H200 itself was unplaceable.

**What to take from it:**

- **Catalog stock is not a reservation.** A "Low" reading can be a host that is
  already held. Runpod's create-pod docs say a create can fail for capacity on
  a GPU the catalog just reported as available.
- **The 400 means one of two things.** It covers both a broken request and no
  capacity, so separate them with a cheap control pod. If the control succeeds,
  the request is fine and the problem is capacity. Disk size, ports and CUDA
  pinning were not the cause.
- **Do not run tight retry loops against the API.** A loop of creates every
  90 s was stopped as spam. Check by hand from time to time, then create once.
- **The image does not limit placement.** A CUDA 12.8 image runs on CUDA 13.2
  hosts.

**Fix the local Claude CLI first if plugin install fails.** Old npm installs of
`@anthropic-ai/claude-code` crash on Node 26. Remove them with
`npm uninstall -g --prefix <prefix> @anthropic-ai/claude-code`, so that
`claude` resolves to a working install.

## Steps (network-volume mode)

Only you can do the steps marked **(you)**. I do not enter credentials or
launch pods.

1. **(you)** In RunPod:
   - Set an account spend limit at or below $497.
   - Add your SSH public key.
   - Create a **1.5 TB network volume** in a data center that offers 8×H200.
2. **(you)** Start a cheap **CPU pod** with the volume at `/workspace` and an
   exposed SSH port.
3. Copy the kit onto the volume. It lives only in local commits, so do not push:

   ```bash
   git archive HEAD | ssh -p PORT root@HOST 'mkdir -p /workspace/keep && tar x -C /workspace/keep'
   ```

4. On the CPU pod:

   ```bash
   bash /workspace/keep/scripts/runpod/v41_reap/pod.sh fetch
   ```

   ```bash
   bash /workspace/keep/scripts/runpod/v41_reap/pod.sh pack
   ```

   - **Check the fetch:** it must end with `fetch verified`, and the printed
     model.py sha256 must be `e5decd76…8b8d2d`.
   - **Check the pack:** read `/workspace/pack/manifest.json` and confirm every
     domain reached its budget. A source that falls short shows up in its
     `filtered`, `off_domain` or `non_english` counts.

   Then stop the CPU pod.
5. **(you)** Start an **8×H200 pod** with the same volume. Pick a PyTorch 2.10+
   / CUDA 12.8+ image and **at least 1 TB of system RAM**, because `convert.py`
   holds the whole checkpoint in memory.
6. On the GPU pod, run inside `tmux`, since the pod stops itself when the stage
   ends or at the limit:

   ```bash
   MAX_GPU_HOURS=6 bash /workspace/keep/scripts/runpod/v41_reap/pod.sh gpu
   ```

   - **Watch the run:** follow `/workspace/out/progress.jsonl` for the first
     sessions.
   - **Results:** `/workspace/out/candidate-scores.json` holds the per-domain
     KL, NLL change and top-1 agreement for N = 256/224/192/160.
   - **Watchdog:** it calls `runpodctl stop pod`. If that fails it logs the
     failure, so also keep the spend limit from step 1 in place.
7. **Choose N** from the scores. Take the smallest N whose worst domain stays
   close to N=256, and which also fits the Mac's disk: 423 GB free, minus
   about 30 GB of stats and logits.
8. **(you)** Start a CPU pod on the volume again, then run:

   ```bash
   bash /workspace/keep/scripts/runpod/v41_reap/pod.sh prune 192
   ```

9. Pull the results to the Mac. Run each transfer as its own command.

   The pruned checkpoint:

   ```bash
   rsync -avP --partial -e "ssh -p PORT" root@HOST:/workspace/v41-reap192/ ~/keep-artifacts/v41-reap192/
   ```

   The stats, logits and pack:

   ```bash
   rsync -avP --partial -e "ssh -p PORT" root@HOST:/workspace/out/ ~/keep-artifacts/v41-runpod-out/
   ```

   ```bash
   rsync -avP --partial -e "ssh -p PORT" root@HOST:/workspace/pack/ ~/keep-artifacts/v41-pack/
   ```

   Then verify the checkpoint:

   ```bash
   cd ~/keep-artifacts/v41-reap192 && shasum -a 256 -c SHA256SUMS --quiet
   ```

10. **(you)** Delete the network volume once the Mac copies verify.

## Notes

- **Survivors:** `reap-select` picks them from calibration stats only. The
  per-layer Jaccard against frequency is in `reap-select-N.json`; a value of
  0.9 or more means REAP added little.
- **Masked student pass:** it sets the router bias of pruned experts to -inf,
  which equals slicing them (`tests/test_reap.py`). One converted checkpoint
  therefore scores every N.
- **Eval sessions carry REAP stats and routes but no imatrix**, so the
  per-split saliency can be compared later.
- **Sizes:** routed experts are about 289 GB of the 510 GB source, roughly
  0.75 GB per expert slot across the 40 layers. Engram (~196 GB) is untouched
  and is most of what is left after pruning.
